# 05. 운영·배포

> 서버사이드 MCP 2종 — systemd + Caddy(HTTPS) + sslip.io
> 작성일: 2026-06-19 · 상태: 초안 · 산출물: `deploy/` · 원이력: `HANDOFF.md`, `deploy/README.md`

## 0. 목표

MCP 서버 2종을 **VPS에서 통제**(systemd)하고 **Caddy HTTPS + Bearer 토큰**으로 노출한다. 로컬에는 node 프로세스도 SSH 터널도 없다 — OpenCode는 **URL 2개만** 본다.

## 1. 토폴로지

```
[로컬 OpenCode] ──HTTPS+Bearer──▶ [VPS Caddy :443  (Let's Encrypt / sslip.io)]
                                     ├─ /postgres/* → 127.0.0.1:8011 (postgres-mcp) → :5434 demo_legacy
                                     └─ /lightrag/* → 127.0.0.1:8012 (lightrag-mcp) → :9621 LightRAG
```

- 두 node 서버는 `127.0.0.1` 전용 바인딩 → **외부 진입점은 Caddy뿐**. TLS는 Caddy, 토큰 검증은 node.
- postgres-mcp가 DB와 같은 박스라 SSH 터널 불필요(localhost:5434 직결).

## 2. 구성 산출물 (`deploy/`)

| 파일 | 역할 |
|------|------|
| `postgres-mcp.service` / `lightrag-mcp.service` | systemd 유닛 (`Restart=on-failure`, `EnvironmentFile`) |
| `postgres-mcp.env.example` / `lightrag-mcp.env.example` | 환경설정 템플릿 (PG_CONN/LIGHTRAG_BASE_URL/MCP_TOKEN/HOST/PORT/MCP_PATH) |
| `Caddyfile` | `{$MCP_DOMAIN}` 가상호스트 + 경로 리버스 프록시 |
| `README.md` | 단계별 배포 가이드(원본) |

> **env 주의:** `PORT`·`MCP_PATH`·`HOST`가 빠지면 Caddy 경로 매칭이 어긋나 404. `.env.example`을 통째 복사하고 토큰만 교체할 것(손타이핑 금지). 기본값: postgres `PORT=8011 MCP_PATH=/postgres/mcp`, lightrag `PORT=8012 MCP_PATH=/lightrag/mcp`.

## 3. 최초 배포 절차

코드는 `/opt/autoever_demo/{postgres-mcp,lightrag-mcp}` 에 위치.

### 3-1. Node + 의존성
```bash
ssh root@72.62.242.236
which node || (curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs)
cd /opt/autoever_demo/postgres-mcp && npm install --omit=dev
cd /opt/autoever_demo/lightrag-mcp && npm install --omit=dev
```

### 3-2. env (chmod 600, 토큰 주입)
```bash
cd /opt/autoever_demo
cp deploy/postgres-mcp.env.example postgres-mcp.env
cp deploy/lightrag-mcp.env.example lightrag-mcp.env
sed -i 's/CHANGE_ME_PASTE_TOKEN/<TOKEN>/' postgres-mcp.env lightrag-mcp.env
chmod 600 postgres-mcp.env lightrag-mcp.env
```
- PG_CONN 포트 = **5434**(VPS 직결). 이미 example에 박힘.

### 3-3. systemd
```bash
cp deploy/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now postgres-mcp lightrag-mcp
curl -s localhost:8011/healthz; curl -s localhost:8012/healthz   # {"ok":true,...}
```

### 3-4. Caddy (HTTPS, 도메인 없이 sslip.io)
`72-62-242-236.sslip.io` → `72.62.242.236` 자동 resolve → Caddy가 **Let's Encrypt 정식 인증서** 발급.
```bash
apt-get install -y caddy
cp deploy/Caddyfile /etc/caddy/Caddyfile
sed -i 's/{$MCP_DOMAIN}/72-62-242-236.sslip.io/' /etc/caddy/Caddyfile   # 환경변수 주입 대신 직접 치환 권장
ufw allow 80/tcp && ufw allow 443/tcp     # 80=ACME 챌린지, 443=서빙 — 둘 다 필수
systemctl restart caddy
```
> ⚠️ 클라우드 보안그룹이 있으면 거기서도 80/443 인바운드 허용 필요(ufw만으론 부족할 수 있음).

### 3-5. 최종 검증 (외부)
```bash
curl -s -X POST https://72-62-242-236.sslip.io/postgres/mcp \
  -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
# → "pg_query","pg_execute" 나오면 DNS+TLS+Caddy+인증+서버 전부 OK. /lightrag/mcp 도 동일.
```

## 4. 운영 명령

| 작업 | 명령 |
|------|------|
| 재시작 | `systemctl restart postgres-mcp lightrag-mcp` |
| 로그 | `journalctl -u postgres-mcp -f` / `-u lightrag-mcp -f` |
| 정지 | `systemctl stop postgres-mcp lightrag-mcp` |
| 상태 | `systemctl status postgres-mcp lightrag-mcp --no-pager` |
| 토큰 교체 | VPS `*.env` 2개 + 클라이언트 OpenCode 설정(전역, `docs/00`) Bearer 갱신 → `systemctl restart` |

## 5. 보안 수칙

- 두 서버 **127.0.0.1 바인딩** 유지(직접 외부 노출 금지). 외부는 Caddy로만.
- `MCP_TOKEN` 미설정 시 서버 **기동 거부**(익명 접근 차단). 헬스체크만 무인증.
- PG_CONN은 `demo_legacy` 로 한정 → 운영 DB `pylon_dev` 격리.
- env 파일 `chmod 600`. 토큰 평문 보관은 데모 한정 — 운영 전환 시 시크릿 매니저 권장.

## 6. 폴백·롤백

- **80포트 못 열 때:** `Caddyfile` 하단 `tls internal`(자체서명) + 로컬 `NODE_TLS_REJECT_UNAUTHORIZED=0 opencode`(보안 약화, 데모 한정). 또는 `cloudflared tunnel`(포트 개방 불필요, URL 가변).
- **로컬 stdio 모드로 롤백:** 각 폴더 `server-stdio.mjs.bak` → `server.mjs` 복사 + `opencode.json`을 `type:"local"`(SSH 터널 15432) 구성으로(원형은 `deploy/README.md` 부록).

## 7. 트러블슈팅

| 증상 | 조치 |
|------|------|
| OpenCode 툴 안 뜸 | `curl .../postgres/mcp tools/list` 200 + 토큰 일치 확인 |
| 401 | OpenCode 설정(전역/프로젝트) Bearer ↔ env `MCP_TOKEN` 불일치 |
| 502 (Caddy) | node 서비스 죽음 → `systemctl status` / 로그 |
| TLS 에러 | 자체서명 사용 중 → 도메인+Let's Encrypt 전환 |
| postgres 연결거부 | VPS에서 5434 포트 / `demo_legacy` 존재 확인 |
