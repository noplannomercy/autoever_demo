# 06. 레거시 패키지 (pkg_collection) — 7막 코드 수정·배포 시연 자산

> 소스·배포·원복·검증. 작성일: 2026-07-02
> 소스: `legacy_src/pkg_collection.sql` (버그 버전 = 시연 시작 상태)

## 0. 개요

demo_legacy에 오라클 패키지를 모사한 스키마 `pkg_collection`을 배포해, "비즈로직이 DB 패키지 안에 있는 레거시"를 재현한다. 파일 헤더는 "원본 Oracle 패키지 4,812라인의 축약 이관본"으로 서사화(현물은 357라인, PL/pgSQL 함수 5개).

**설계 핵심 — 갭3의 원인 코드:** `f_calc_penalty`(위약금 산정)는 고객 등급을 조회하지 않고 전 계약에 원금×2%를 부과한다. 소스 주석(172~173행)에 "등급별 예외는 영업지원팀 수기 정정으로 운영 중"이라고 명시 — **코드는 전부 부과 → 수기 정정 관행 → 4건 누락 = 갭3**이라는 인과가 데이터와 100% 정합한다(하단 §3 검증).

## 1. 함수 구성

| 함수 | 역할 | 근거 규정 | 쓰기 |
|------|------|----------|------|
| `f_calc_monthly_bill(contract_id, ym)` | 월 정기 청구액 | 규정_01 | — |
| `f_calc_delinq_interest(contract_id, asof)` | 연체이자 (365 고정) | 규정_07 | — |
| **`f_calc_penalty(contract_id)`** | **중도해지 위약금 — VIP 면제 누락(버그)** | 규정_05 | — |
| `sp_apply_deposit(deposit_id)` | 입금 충당 (연체이자→이자→원금→수수료) | 규정_02 | deposit_detail |
| `sp_nsf_convert(deposit_id)` | NSF 익일 연체전환 | 규정_04 | delinquency |

- 쓰기 함수 2개는 **재실행 가드**(기충당/기전환 시 0 반환) — 시연 중 오호출돼도 데이터 안 깨짐.
- 전 함수에 COMMENT 부착 (1막 탐색에서 함수도 dict처럼 읽힘).

## 3. 검증 쿼리 (배포 후 / 리허설)

```sql
-- 버그 버전 확인 + 갭3 인과 정합 (기대: 4행 전부 match=true)
SELECT b.contract_id, pkg_collection.f_calc_penalty(b.contract_id) AS calc, b.amount AS billed,
       pkg_collection.f_calc_penalty(b.contract_id) = b.amount AS match
FROM billing b JOIN loan_contract lc ON lc.contract_id=b.contract_id
JOIN customer c ON c.customer_id=lc.customer_id
WHERE b.bill_type='중도해지위약금' AND c.grade='VIP' AND b.amount>0 ORDER BY 1;
-- 실측(2026-07-02): 63→1,460,000 / 133→1,060,000 / 203→660,000 / 273→260,000 (합 3,440,000)

-- 전체 데이터 정합 (기대: 0, 0, 0)
SELECT
 (SELECT count(*) FROM billing b JOIN loan_contract lc ON lc.contract_id=b.contract_id
   JOIN customer c ON c.customer_id=lc.customer_id
  WHERE b.bill_type='중도해지위약금' AND c.grade='일반'
    AND pkg_collection.f_calc_penalty(b.contract_id) <> b.amount) AS penalty_normal_mismatch,
 (SELECT count(*) FROM billing b WHERE b.bill_type='정기'
   AND pkg_collection.f_calc_monthly_bill(b.contract_id, b.bill_ym) <> b.amount) AS bill_mismatch,
 (SELECT count(*) FROM delinquency dl
   WHERE pkg_collection.f_calc_delinq_interest(dl.contract_id, dl.start_date) <> dl.overdue_interest) AS delinq_mismatch;
```

> 패키지가 정기 청구 전건·연체 전건·위약금 전건을 "설명"하는 상태 — 시연 중 어떤 계약을 찍어도 코드와 데이터가 어긋나지 않는다.

## 4. 역문서 (LightRAG 연동)

- `rules/역문서_PKG_COLLECTION.md` — 코드 사실만 서술(갭 판단은 에이전트 몫). `ingest_rules.mjs`로 적재, `clean_kb.mjs` 보존 접두에 `역문서_` 등록됨.
- 검색 실측(2026-07-02): "위약금 어느 코드에서 계산해?" → 역문서 1순위, 함수명·행번호 정확. **주의:** 역문서 적재 후 일반형 질의("충당 우선순위가 뭐야?")는 역문서가 인용될 수 있음 → 규정 질의는 "**규정상**"을 붙일 것(문서 04 §3막 노트).
- 7막에서 코드 수정 후 역문서 갱신·재적재 시: LightRAG는 동일 file_source 재삽입을 409로 막으므로 **기존 문서 삭제 후 재적재**(`clean_kb.mjs`의 delete_document 참조) 또는 파일명 버전 접미(`역문서_PKG_COLLECTION_v2.md`) 사용.
