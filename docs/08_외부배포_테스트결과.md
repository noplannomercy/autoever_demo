## 1. 최종 구성

```
[로컬 OpenCode] ──HTTPS+Bearer──▶ [신규 VPS Caddy :443  (Let's Encrypt / 72-62-242-236.sslip.io)]
                                     ├─ /postgres/* → 127.0.0.1:8011 (postgres-mcp) → :5434 demo_legacy
                                     └─ /lightrag/* → 127.0.0.1:8012 (lightrag-mcp) → :9621 LightRAG
                                                                                        └─ 스토리지: :5434 lightrag DB
```

구서버 대비 변경점:

| 항목 | 구서버 | 신서버 |
|------|--------|--------|
| LightRAG 스토리지 PG | 호스트 PostgreSQL 16 (:5433) | **컨테이너 PG(:5434)로 단순화** — PG가 컨테이너 하나뿐 |
| 호스트 PostgreSQL | 별도 존재(:5433) | **없음** (설치 안 함) |
| MCP_TOKEN | 0acf2a24… (구) | **842c6412…bccba (신규 발급)** |
| 80포트 | — | Hostinger 기본 apache2 제거(disable) 후 Caddy가 사용 |

### PostgreSQL은 어디에 설치됐나

**호스트에 직접 설치하지 않았다.** Docker 컨테이너 `postgres-vector` 하나뿐이다.

- 이미지: `lightrag-pg:16-vector-age` (직접 빌드 — §2-2)
- 포트: 호스트 `5434` → 컨테이너 5432
- 데이터: docker named volume **`postgres-vector-data`** (`/var/lib/docker/volumes/postgres-vector-data/_data`)
- DB 2개: `demo_legacy`(데모 데이터) / `lightrag`(KB 벡터·KV 스토리지)
- 접속: `docker exec -it postgres-vector psql -U postgres -d demo_legacy` (5434는 127.0.0.1 전용 — 외부에선 SSH 터널 `ssh -L 5434:localhost:5434 root@72.62.242.236`)

### Apache AGE는 깔았나

**이미지에 컴파일되어 들어 있으나(1.6.0), 어느 DB에도 활성화(CREATE EXTENSION)하지 않았다.** 그래서 `\dx`에 안 보인다.

> **결정(2026-07-09): AGE 미사용 확정.** 현 아키텍처(LightRAG 호출 처리, 그래프=NetworkX 파일)에서 역할이 없음. 이미지에서 제거하지는 않음(재빌드 비용 대비 이득 없음, 향후 PGGraphStorage 전환 시 CREATE EXTENSION 한 줄로 활성화 가능한 보험).

- 데모는 AGE를 쓰지 않는다 — LightRAG 그래프 스토리지가 `NetworkXStorage`(파일 기반, `/opt/lightrag/rag_storage/`)이고, PG는 벡터(`PGVectorStorage`, pgvector)와 KV만 담당.
- 구서버도 `lightrag` DB에 age가 활성화만 돼 있었을 뿐 실사용처는 없었다.
- 나중에 필요하면 한 줄로 활성화 가능: `docker exec postgres-vector psql -U postgres -d <DB> -c "CREATE EXTENSION age;"`
- 현재 상태: `pg_available_extensions` 기준 age 1.6.0 / vector 0.8.4 **available**, 활성화는 `lightrag` DB에 vector만.

## 2. 설치 절차 (실제 실행 내역)

로컬(작업 PC)에서 SSH로 원격 실행. 사전에 공개키(`~/.ssh/id_ed25519.pub`)를 서버 `authorized_keys`에 등록.

### 2-1. 기본 패키지
```bash
apt-get update
apt-get install -y docker.io git curl jq python3-venv python3-pip
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs   # v20.20.2
# Caddy 공식 저장소
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt > /etc/apt/sources.list.d/caddy-stable.list
apt-get update && apt-get install -y caddy   # v2.11.4
```

### 2-2. 커스텀 PG 이미지 빌드 + 컨테이너
Dockerfile은 구서버 `/opt/lightrag/docker/Dockerfile.pg-age` 에서 복사 (베이스 `pgvector/pgvector:pg16` + Apache AGE PG16 브랜치 소스 컴파일).
```bash
docker build -t lightrag-pg:16-vector-age -f Dockerfile.pg-age .
docker run -d --name postgres-vector --restart unless-stopped \
  -e POSTGRES_PASSWORD=<PG_PASSWORD> -p 127.0.0.1:5434:5432 \
  -v postgres-vector-data:/var/lib/postgresql/data lightrag-pg:16-vector-age
docker exec postgres-vector psql -U postgres -c "CREATE DATABASE demo_legacy;" -c "CREATE DATABASE lightrag;"
docker exec postgres-vector psql -U postgres -d lightrag -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

### 2-3. 데모 데이터 적재
로컬 `data/01_demo_data.sql` 업로드 후:
```bash
docker exec -i postgres-vector psql -U postgres -d demo_legacy < 01_demo_data.sql
# 말미 검증표: ★갭1=6 · ★갭2=5 · ★갭3=4  ← 이 숫자가 정확히 나와야 정상
```

### 2-4. LightRAG (버전 고정)
```bash
mkdir -p /opt/lightrag/{inputs,logs,rag_storage}
cd /opt/lightrag && python3 -m venv .venv
.venv/bin/pip install "lightrag-hku[api]==1.5.3"        # 구서버와 동일 버전
# .env: 구서버 /opt/lightrag/.env 복사 후 3줄만 수정
#   POSTGRES_HOST=localhost / POSTGRES_PORT=5434 / POSTGRES_PASSWORD=<PG_PASSWORD>
chmod 600 .env
# systemd 유닛(lightrag.service) 등록 → enable --now
```
`.env`에 OpenRouter(LLM)·OpenAI(임베딩) API 키 포함 — 서버 간 직접 복사로 이관(§5 키 교체 절차 참고).

### 2-5. MCP 서버 2종
로컬 `autoever_demo/{postgres-mcp,lightrag-mcp,deploy,data,rules,...}` → `/opt/autoever_demo` 업로드 후:
```bash
cd /opt/autoever_demo/postgres-mcp && npm install --omit=dev
cd /opt/autoever_demo/lightrag-mcp && npm install --omit=dev
cd /opt/autoever_demo
cp deploy/postgres-mcp.env.example postgres-mcp.env
cp deploy/lightrag-mcp.env.example lightrag-mcp.env
TOK=$(openssl rand -hex 32)                              # 신규 토큰 발급
sed -i "s/CHANGE_ME_PASTE_TOKEN/$TOK/" postgres-mcp.env lightrag-mcp.env
chmod 600 postgres-mcp.env lightrag-mcp.env
cp deploy/*.service /etc/systemd/system/ && systemctl daemon-reload
systemctl enable --now postgres-mcp lightrag-mcp
```

### 2-6. Caddy HTTPS
```bash
systemctl disable --now apache2                          # Hostinger 기본 apache2가 :80 점유 → 제거
cp deploy/Caddyfile /etc/caddy/Caddyfile
sed -i 's/{$MCP_DOMAIN}/72-62-242-236.sslip.io/' /etc/caddy/Caddyfile
systemctl restart caddy                                  # Let's Encrypt 자동 발급 확인
```
ufw는 inactive 상태라 별도 개방 불필요했음 (Hostinger 패널 방화벽 사용 시 80/443 인바운드 확인).

### 2-7. 규정 13장 ingest
```bash
# ⚠️ rules/역문서_PKG_COLLECTION.md 는 KB 대상 아님(설계 원칙: KB=손으로 쓴 규정 13장만)
#    → ingest 전에 rules/ 밖으로 이동해둠 (/opt/autoever_demo/ 에 위치)
cd /opt/autoever_demo/rules
LIGHTRAG_BASE_URL=http://127.0.0.1:9621 node ingest_rules.mjs   # 13건 전부 200
```

### 2-8. 로컬 반영
`opencode.json`·`SETUP.md`·`HANDOFF.md`·`deploy/`·`rules/*.mjs`·`docs/00·01·04·05·06·07` 의 IP/토큰을 신서버 값으로 일괄 치환. (`docs/superpowers/` 하위 날짜 박힌 설계·플랜 문서는 이력 보존을 위해 미변경.)

⚠️ **놓치기 쉬운 것: OpenCode 전역설정.** 실제 연결은 프로젝트 `opencode.json`이 아니라 **전역설정**(`~/.config/opencode/opencode.json`·`opencode.jsonc`)의 `mcp` 블록을 쓴다(docs/00 §2-2). 서버 주소/토큰 변경 시 **전역설정도 반드시 갱신 + OpenCode 재시작.** (당일 테스트에서 이 누락으로 "MCP 동작 안 함" 발생 → 전역설정 갱신으로 해결.)

## 3. 테스트 방법 & 결과

전부 재실행 가능한 명령. 당일 결과는 ✅ 표기.

### 3-1. 서비스 생존 (서버에서)
```bash
for s in docker caddy lightrag postgres-mcp lightrag-mcp; do systemctl is-active $s; done   # 전부 active
curl -s localhost:8011/healthz    # {"ok":true,"name":"postgres-mcp"}
curl -s localhost:8012/healthz    # {"ok":true,"name":"lightrag-mcp",...}
curl -s localhost:9621/health     # {"status":"healthy",...}
```
✅ 5개 서비스 enabled+active, healthz 3종 정상.

### 3-2. 데이터 갭 검증 (서버에서)
```bash
docker exec postgres-vector psql -U postgres -d demo_legacy -c \
 "SELECT (SELECT count(*) FROM loan_contract) contracts, (SELECT count(*) FROM deposit) deposits;"
```
✅ contracts 3000 / deposits 2104. 적재 시 검증표 ★6/★5/★4 일치.

### 3-3. KB 검증 (어디서든)
```bash
# 9621은 외부 차단(ufw) — 서버에서 실행
curl -s http://127.0.0.1:9621/documents   # 13건 전부 "processed"
curl -s -X POST http://127.0.0.1:9621/query -H "Content-Type: application/json" \
  --data-binary '{"query":"입금 충당 우선순위 순서가 뭐야?","mode":"mix","include_references":true}'
```
✅ "연체이자→이자→원금→수수료" + `회수규정_02_입금충당우선순위.md` 인용.

### 3-4. 외부 게이트웨이 E2E (로컬에서)
```bash
TOK="<MCP_TOKEN>"
# 툴 목록 (postgres → pg_query/pg_execute, lightrag → lightrag_query)
curl -s -X POST https://72-62-242-236.sslip.io/postgres/mcp \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
# 무토큰 → 401 확인
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://72-62-242-236.sslip.io/postgres/mcp \
  -H "Content-Type: application/json" -d '{}'
```
✅ 툴 노출 정상 / 무토큰 401 / HTTPS로 SQL 실행(tools/call pg_query)까지 응답 확인.

### 3-5. 데모 리허설 (OpenCode)

## 5. OpenRouter / OpenAI 키 교체 절차

키는 **서버의 `/opt/lightrag/.env` 한 곳**에만 있다 (MCP env에는 없음).
```bash
ssh root@72.62.242.236
sed -i 's|^  LLM_BINDING_API_KEY=.*|  LLM_BINDING_API_KEY=<새 OpenRouter 키>|' /opt/lightrag/.env
# 임베딩(OpenAI) 키 교체 시: EMBEDDING_BINDING_API_KEY 줄 동일 방식
systemctl restart lightrag
# 검증: §3-3 query가 정상 응답하면 OK (query는 LLM 키, 신규 문서 적재는 임베딩 키 사용)
```
> 참고: 키가 죽어도 **검색 자체의 임베딩은 이미 적재된 벡터를 쓰지만, query 응답 생성(LLM)과 질의 임베딩은 살아있는 키가 필요.** 교체 후 반드시 query 1회로 확인.
