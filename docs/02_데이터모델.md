# 02. 데이터 모델

> demo_legacy — 회수 도메인 8테이블 · 합성 데이터 · 갭 3종
> 작성일: 2026-06-19 · 상태: 초안 · 원본 SQL: `data/01_demo_data.sql`

## 0. 개요

Postgres MCP가 조회하는 **레거시 실데이터 역할**의 합성 DB다. 현대캐피털 여신/할부의 **청구·회수 생명주기**를 8테이블로 모델링했고, 데이터는 전부 `generate_series` 합성이며, **코드↔규정 갭 3종**을 결정적(deterministic)으로 심어 검증 가능하게 했다.

- DB: `demo_legacy` (컨테이너 `postgres-vector`, 호스트 `:5434`). 운영 DB `pylon_dev`와 격리.
- 멱등: SQL 재실행 시 전체 DROP→재생성.
- 적재: `docker exec -i postgres-vector psql -U postgres -d demo_legacy < 01_demo_data.sql`
- **dict 모사:** 모든 테이블·컬럼에 한글 `COMMENT`(데이터 사전) 부착 → 1막 탐색 시 에이전트가 `col_description`으로 의미를 인라인으로 읽음. 실 레거시(코어 테이블 주석율 88%) 구조 모사.

## 1. 청구·회수 생명주기

```
계약(loan_contract)
   │ 약정 시점
   ▼
월 상환 스케줄(repayment_schedule)   ← 회차별 원금/이자 분할표
   ▼
월 청구(billing)                      ← 정기 청구 + 중도해지위약금
   ▼
입금(deposit) ─── 입금 상세=충당(deposit_detail)   ← 원금/이자/연체이자 배분
   │  └ NSF(자동이체 실패)
   ▼
연체(delinquency)                     ← 단계·연체이자
```

## 2. ERD (관계)

```
customer 1───∞ loan_contract ∞───1 product
                   │
      ┌────────────┼───────────────┬───────────────┐
      ▼            ▼               ▼               ▼
repayment_     billing         deposit         delinquency
 schedule                         │
                                  ▼
                            deposit_detail
```

| 외래키 | 참조 |
|--------|------|
| `loan_contract.customer_id` | `customer.customer_id` |
| `loan_contract.product_code` | `product.product_code` |
| `repayment_schedule.contract_id` | `loan_contract.contract_id` |
| `billing.contract_id` | `loan_contract.contract_id` |
| `deposit.contract_id` | `loan_contract.contract_id` |
| `deposit_detail.deposit_id` | `deposit.deposit_id` |
| `delinquency.contract_id` | `loan_contract.contract_id` |

## 3. 테이블 명세

행수는 적재 검증 실측값(2026-06-19).

### 3.1 `customer` — 고객 (2,000행)
| 컬럼 | 타입 | 의미 |
|------|------|------|
| customer_id | int PK | 고객 ID |
| name | text | 고객명(`고객00001`…) |
| grade | text | `VIP`(10%) / `일반` |
| credit_score | int | 신용점수 |
| annual_income | int | 연소득(만원) |
| dti | numeric(5,2) | 총부채원리금상환비율(%) |

### 3.2 `product` — 상품 (8행)
| 컬럼 | 타입 | 의미 |
|------|------|------|
| product_code | text PK | `P01`~`P08` |
| product_name / product_type | text | 상품명 / `신용대출·담보대출·오토할부·리스` |
| auto_approve_yn | char(1) | 자동승인 여부 |
| max_dti | numeric(5,2) | 자동승인 DTI 상한 |
| **delinquent_rate** | numeric(4,2) | 연체이자율(%) — 회수규정_07 |
| **prepay_fee_rate** | numeric(4,2) | 중도상환수수료율(%) — 회수규정_08 |

### 3.3 `loan_contract` — 계약 (3,000행)
| 컬럼 | 타입 | 의미 |
|------|------|------|
| contract_id | int PK | 계약 ID |
| customer_id / product_code | FK | 고객 / 상품 |
| principal | bigint | 원금(원) |
| interest_rate | numeric(4,2) | 약정 금리(%) |
| term_months | int | 약정 개월(12~60) |
| status | text | `정상·완납·중도해지·연체` |
| start_date | date | 약정일 |

> 상태 분포 규칙: `g%7=0`→중도해지, `g%11=0`→연체, `g%5=0`→완납, 그 외 정상.

### 3.4 `repayment_schedule` — 월 상환 스케줄 (12,624행)
정상·연체 계약에 6회차 생성. `installment_no·due_date·principal_due·interest_due·total_due·status(완납/예정/연체)`.

### 3.5 `billing` — 월 청구 (2,532행)
| 컬럼 | 의미 |
|------|------|
| bill_ym | 청구 년월(YYYYMM) |
| bill_type | `정기` / `중도해지위약금` |
| amount / due_date / status | 청구액 / 납기 / `미납·완납` |

- 정기: 정상·연체 계약, 2026-06.
- 중도해지위약금: 중도해지 계약. 일반=원금×2% 부과, VIP=0(면제) — **단 갭3 대상은 예외**(§4).

### 3.6 `deposit` — 입금 내역 (2,104행)
| 컬럼 | 의미 |
|------|------|
| paid_date / amount / method | 입금일 / 금액 / `자동이체·가상계좌` |
| **nsf_yn** | `Y`=자동이체 출금 실패(잔액부족) / `N`=정상 |

- 정상 계약: 정상 납입(nsf_yn=N). 연체 계약: 자동이체 실패(nsf_yn=Y, 금액 0).

### 3.7 `deposit_detail` — 입금 상세=충당 (5,610행)
| 컬럼 | 의미 |
|------|------|
| alloc_type | 충당 대상 `연체이자·이자·원금` |
| **alloc_seq** | 충당 순서(작을수록 먼저) |
| amount | 충당액 |

> 규정상 순서(회수규정_02): 연체이자→이자→원금→수수료. **갭1 대상만 원금을 먼저 충당**(§4).

### 3.8 `delinquency` — 연체 (229행)
연체 계약의 연체전환 기록. `start_date·overdue_days·overdue_principal·overdue_interest·stage(1/2/3단계)`. 연체이자 = 연체원금 × delinquent_rate ÷ 365 × 연체일수.

## 4. 심어둔 갭 3종 (★ 핵심)

각 갭은 "**규정(LightRAG)은 X인데 데이터(Postgres)는 Y**"인 불일치를, 결정적 predicate로 심어 **정확한 건수**가 검증 쿼리로 떨어진다. 실측 결과(2026-06-19): **6 / 5 / 4건**.

### 갭1 — 입금 충당 순서 위반 (6건)
- **규정(회수규정_02):** 연체이자 → 이자 → 원금 순 충당.
- **심는 법:** 정상 계약 입금 중 `deposit_id` 작은 **6건**에 한해 원금 `alloc_seq=1`, 연체이자 `alloc_seq=3` (순서 역전).
- **검출:**
```sql
SELECT count(DISTINCT dd1.deposit_id)
FROM deposit_detail dd1 JOIN deposit_detail dd2 ON dd2.deposit_id=dd1.deposit_id
WHERE dd1.alloc_type='원금' AND dd2.alloc_type='연체이자'
  AND dd1.alloc_seq < dd2.alloc_seq AND dd2.amount>0;   -- = 6
```
- **실측 대상:** deposit_id 1~6 (contract_id 1,2,3,4,6,8).

### 갭2 — NSF 연체전환 누락 (5건)
- **규정(회수규정_04):** NSF면 익일 연체전환(`delinquency` 행 생성).
- **심는 법:** 연체 계약 중 `contract_id` 작은 **5건**은 `delinquency` 행을 생성하지 않음(NSF인데 전환 누락).
- **검출:**
```sql
SELECT count(*) FROM deposit d
WHERE d.nsf_yn='Y'
  AND NOT EXISTS (SELECT 1 FROM delinquency dl WHERE dl.contract_id=d.contract_id);  -- = 5
```
- **실측 대상:** contract_id 11,22,33,44,55.

### 갭3 — VIP 중도해지 위약금 오부과 (4건)
- **규정(회수규정_05):** VIP는 중도해지 위약금 전액 면제.
- **심는 법:** VIP 중도해지 계약 중 `contract_id` 작은 **4건**에 위약금(원금×2%) 부과.
- **검출:**
```sql
SELECT count(*), sum(b.amount) FROM billing b
JOIN loan_contract lc ON lc.contract_id=b.contract_id
JOIN customer c ON c.customer_id=lc.customer_id
WHERE b.bill_type='중도해지위약금' AND c.grade='VIP' AND b.amount>0;  -- = 4건, ₩3,440,000
```
- **실측 대상:** contract_id 63,133,203,273 (합계 ₩3,440,000).
