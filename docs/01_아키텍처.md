## 1. 한 줄 정의

**하나의 에이전트가 두 개의 도구**(구조화 데이터 + 비구조 지식)를 교차 호출해, "**실제로 어떤가**"와 "**규정상 어떻게 해야 하나**"를 대조하고 **갭을 짚어내는** agentic RAG.

- **Postgres MCP** = 레거시 실데이터 행 ("이 건 실제 값이 뭔가")
- **LightRAG MCP** = 규칙/규정/역문서 의미층 ("왜 / 규정상 어떻게 돼야 하나")
- **킬러 가치** = 한쪽 도구만으로는 절대 못 나오는 답(실데이터 ∩ 규정 = 갭).

## 2. 제품 논지 (왜 이게 제품인가)

이 데모는 특정 고객(현대캐피털) 회수 업무를 무대로 쓰지만, 본질은 **도메인 무관한 패턴**이다.

> 어느 기업이든 "**트랜잭션 데이터(DB)** + **사내 규정/매뉴얼/약관(문서)**" 구조를 갖는다.
> 운영 담당자는 늘 "데이터가 실제로 이런데, 규정상 맞나?"를 묻는다.
> 그 질문에 두 소스를 자동 대조해 답하는 코파일럿이 곧 제품이다.

회수 도메인을 고른 이유: ① 모든 여신/할부사가 가진 보편 업무라 일반화가 쉽고, ② "실데이터도 봐야 하고 규정도 봐야 하는" 전형이라 2-tool 가치가 가장 선명하며, ③ 현대캐피털 피치로 그대로 전환된다.

## 3. 시스템 개요

```
┌─────────────────────────── 로컬 (사용자 노트북) ───────────────────────────┐
│  OpenCode (에이전트 런타임)                                                  │
│    ├─ opencode.json   : remote MCP 2개 URL + Bearer 토큰                    │
│    └─ AGENTS.md       : 행동 지침(갭 탐지·근거 분리·읽기/쓰기 안전수칙)      │
└───────────────────────────────────┬────────────────────────────────────────┘
                                     │  HTTPS + Bearer  (Streamable HTTP / JSON-RPC)
                                     ▼
┌──────────────────────────────── VPS (72.62.242.236) ──────────────────────┐
│  Caddy  :443   (TLS 종단: Let's Encrypt via sslip.io)                        │
│    ├─ handle /postgres/*  → 127.0.0.1:8011                                   │
│    └─ handle /lightrag/*  → 127.0.0.1:8012                                   │
│                                                                             │
│  postgres-mcp (node, :8011, 127.0.0.1)      lightrag-mcp (node, :8012)       │
│    · pg_query  (읽기: SELECT/WITH/EXPLAIN)     · lightrag_query              │
│    · pg_execute(쓰기/DDL, 명시 요청만)            (include_references 자동)   │
│         │                                            │                       │
│         ▼                                            ▼                       │
│  postgres-vector 컨테이너 :5434              LightRAG :9621                   │
│    DB demo_legacy  (회수 8테이블)              회수 규정 13장 (PG 스토리지)   │
│    ※ pylon_dev 격리(접근 불가)                 LLM=gpt-4o-mini / embed=3-small│
└─────────────────────────────────────────────────────────────────────────────┘
```

핵심: **MCP 서버가 데이터/지식과 같은 박스(VPS)에서 돌아** SSH 터널·로컬 node가 필요 없다. 로컬 OpenCode는 **URL 2개만** 본다.

## 4. 컴포넌트

### 4.1 OpenCode (에이전트 런타임, 로컬)
- 사용자 질의를 받아 LLM이 **자율적으로 도구를 선택·호출**하는 agentic 루프.
- `opencode.json` — 두 remote MCP(`type:"remote"`) URL과 `Authorization: Bearer <token>` 헤더.
- `AGENTS.md` — 시스템 지침. ① 규칙 질문은 LightRAG, 데이터 질문은 Postgres, 둘 다 필요하면 둘 다. ② **갭 탐지가 핵심** — 데이터와 규정이 어긋나면 명시적으로 지적. ③ 모든 답 끝에 **「근거」 블록**(데이터쪽/규칙쪽 출처 분리). ④ 쓰기(pg_execute)는 사용자가 명시 요청 시에만 + 전후 대조.

### 4.2 Caddy (TLS 게이트웨이, VPS :443)
- 도메인이 없어 **sslip.io** 와일드카드 DNS 사용: `72-62-242-236.sslip.io` → `72.62.242.236` 자동 resolve → Caddy가 **Let's Encrypt 정식 인증서** 발급(OpenCode가 그대로 신뢰).
- 경로 기반 리버스 프록시(`/postgres/*`→8011, `/lightrag/*`→8012). 두 node 서버는 `127.0.0.1` 바인딩이라 **외부 진입점은 Caddy뿐.**

### 4.3 postgres-mcp (node, :8011)
- MCP 도구 2개:
  - **`pg_query(sql)`** — 읽기 전용. 정규식으로 `select|with|explain`만 허용, 그 외 거부. 결과 행을 JSON으로(최대 200행, bigint 문자열화).
  - **`pg_execute(sql)`** — 쓰기/DDL. AGENTS.md 안전수칙과 결합해 명시 요청 시에만.
- `PG_CONN`으로 **`demo_legacy` 한 DB에만** 묶임 → `pylon_dev` 접근 원천 차단.
- Transport: **Streamable HTTP, stateless**(요청마다 새 server+transport, 세션 ID 없음).

### 4.4 lightrag-mcp (node, :8012)
- MCP 도구 1개: **`lightrag_query(query, mode)`** — LightRAG `/query`를 호출(`mode` 기본 `mix` = 벡터+그래프, `include_references:true` 강제).
- 응답에서 **실제 인용된 출처 문서만 추려** "── 출처 문서 ──" 블록을 덧붙임 → 환각 방지·근거 강제.
- LightRAG REST(`:9621`)의 얇은 래퍼. 키 없음(auth disabled, 로컬 바인딩이라 무방).

### 4.5 데이터 계층
- **Postgres** — `postgres-vector` 컨테이너(호스트 5434). DB `demo_legacy`에 회수 도메인 **8테이블**(상세 → 문서 02). 합성 데이터, 갭 3종 결정적 심김.
- **LightRAG** — `:9621`, 회수 규정 **13장** 적재(상세 → 문서 03). 스토리지는 Postgres(PGKVStorage 등), LLM=OpenRouter `gpt-4o-mini`, 임베딩=OpenAI `text-embedding-3-small`.

## 5. 데이터 흐름 — 킬러 질의 한 건 (end-to-end)

예: "이번 분기 중도해지 중 위약금 정책 위반 있어?"

1. OpenCode LLM이 질의를 받고 **두 도구가 다 필요**하다고 판단.
2. `pg_query` 호출 → Caddy→8011→demo_legacy: `billing`(중도해지위약금) ∩ `customer`(VIP) ∩ `amount>0` 조회 → **4건** 반환.
3. `lightrag_query` 호출 → Caddy→8012→LightRAG: "VIP 위약금" → `회수규정_05` "VIP 전액 면제" + 출처 반환.
4. LLM이 대조: 규정=면제인데 데이터=부과 → **"VIP 4건 위약금 오부과 = 정책 위반 갭"**.
5. 답변 끝에 「근거」 블록: `[데이터·Postgres] billing/customer (contract_id 63,133,203,273)` / `[규칙·LightRAG] 회수규정_05`.

## 6. 트랜스포트 · 배포

| 항목 | 방식 |
|------|------|
| MCP 트랜스포트 | Streamable HTTP, **stateless** (GET/DELETE 405, POST만) |
| 프로토콜 | JSON-RPC 2.0 (`tools/list`, `tools/call`) over HTTPS |
| 프로세스 관리 | **systemd** (`postgres-mcp.service`, `lightrag-mcp.service`, `Restart=on-failure`) |
| TLS·라우팅 | **Caddy** + Let's Encrypt + sslip.io |
| 환경설정 | `*.env`(chmod 600) — PG_CONN/LIGHTRAG_BASE_URL/MCP_TOKEN/PORT/MCP_PATH |
| 코드 위치(VPS) | `/opt/autoever_demo/{postgres-mcp,lightrag-mcp}` |
| 롤백 | 각 폴더 `server-stdio.mjs.bak` → `server.mjs` (옛 stdio 로컬 모드) |

> stateless를 택한 이유: 데모는 동시성·세션 상태가 불필요하고, 요청마다 새 server/transport가 요청 ID 충돌을 원천 차단해 단순·견고하다.

## 7. 보안

- **인증** — 두 MCP 모두 `MCP_TOKEN` Bearer 필수(미설정 시 기동 거부). 헬스체크(`/healthz`)만 무인증.
- **노출 최소화** — node 서버는 `127.0.0.1`만 바인딩. 외부는 Caddy(:443)로만. 토큰 검증은 node, TLS는 Caddy.
- **쓰기 분리** — 읽기(`pg_query`)와 쓰기(`pg_execute`) 도구 분리 + 정규식 가드. 쓰기는 AGENTS.md 수칙(실행 전 계획·전후 대조·WHERE 필수)과 결합.
- **DB 스코프** — `PG_CONN`이 `demo_legacy`로 한정 → 운영 DB(`pylon_dev`) 격리.
- **데모 한계** — 토큰 평문 보관(env 600), sslip.io 의존, LightRAG 자체는 무인증(로컬 바인딩 전제). 운영 전환 시 강화 대상(→ §9).

## 9. 알려진 한계 · 운영 전환 시 과제

- **합성 데이터 / 목업 규정** — 제품 검증용. 실 적용 시 실데이터·실규정으로 교체.
- **단일 VPS, 단일 토큰** — 멀티테넌시·키 로테이션·감사로그 없음.
- **LightRAG 무인증** — 로컬 바인딩 전제. 외부 분리 시 인증 필요.
- **stateless 트랜스포트** — 대화형 스트리밍/장기 세션 필요 시 재설계.
- **검색 정확도** — 규정 13장 규모에서 갭 질의 retrieval 정확 확인됨(문서 03). KB가 더 커지면 재검증 필요.
