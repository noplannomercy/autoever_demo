## 프롬프트 (여기부터 복사)

너는 시연 중심 발표 자료를 만드는 디자인 리드다. 아래 요구사항대로 **의존성 0의 단일 HTML 프레젠테이션 덱**을 만들어라.

### 0. 입력 (채워 넣기)

- **프로젝트**: [프로젝트명과 한 줄 정의]
- **청중**: [혼합(임원+실무) / 임원 / 실무]
- **시연 시나리오**: [단일 스토리 아크로 서술 — 문제 발견 → 원인 → 조치 → 검증. 문서가 있으면 경로 지정]
- **실측 수치**: [시연에서 나오는 모든 숫자를 나열. 이 숫자만 쓰고 절대 지어내지 말 것]
- **기술 스택**: [실제 구동 중인 컴포넌트 목록 — 이름·역할·포트]
- **핵심 한 문장**: [청중이 하나만 기억한다면 남길 문장]

### 1. 산출물 형식

- 단일 `.html` 파일. 외부 리소스 금지(웹폰트 CDN·외부 이미지·JS 프레임워크 없음) — 폐쇄망 브라우저에서 더블클릭으로 열려야 한다. 다이어그램은 인라인 SVG.
- 키보드: ←→/Space 넘김, Home/End, R=연출 재생, N=노트, V=발표자 보기, T=타이머 리셋, P=인쇄.
- 하단 골드 진행 바 + 좌측 세로 골드 룰 + 파트 라벨 + 페이지 번호.
- 인쇄: `@page` 16:9 가로·여백 0, 장당 1페이지, 연출 없이 완성 상태로.
- URL 해시(#N)로 특정 슬라이드 직행 가능.

### 2. 내러티브 — 콜드 오픈, 20장 내외

순서: **훅(결과부터) → 문제 → 무대 소개 → 오늘의 룰 → [다크 전환] → 시연 장면들 → 정직성(환각 방지) → 스코어보드 → 아키텍처 → 실물 스택 → 안전장치 → 로드맵 → 검증 완료 → 클로징**.

- 슬라이드당 **선언문 1개 + 증명 비주얼 1개**. 불릿 나열 금지(최대 3개).
- 숫자가 주인공: 히어로 수치 4~5개를 초대형 모노스페이스 타이포로 반복 등장시켜 기억에 박아라.
- 시연 파트는 **단일 스토리**로만. 곁가지 시나리오는 스코어보드 1장으로 요약하고, 상세는 별도 FAQ 문서로 뺀다(본편에 넣지 마라).
- 시연 장면은 "에이전트가 일하고 → 사람이 검증한다"의 교차 리듬. 사람 검증 장면엔 골드 원형 배지(①②③).
- 극장 구조: **다크 오프닝 → 라이트 본문 → 다크 시연 전환("지금부터, 에이전트가 일합니다") → 라이트 → 다크 클로징**. 오프닝 배경엔 문제를 상징하는 거대 반투명 글리프, 클로징엔 결과를 상징하는 글리프로 수미상관.

### 3. 디자인 시스템

- 팔레트: 배경 `#FAF9F6` / 잉크 `#0F2440` / 골드 `#C9A227` / 경고 레드 `#C43D2F` / 검증 그린 `#1E7A46` / 다크 패널 `#0D1B2A`.
- 타이포: 본문 `Pretendard → 'Noto Sans KR' → 'Malgun Gothic'` 시스템 폴백, 코드·숫자 `'D2Coding', Consolas` + `tabular-nums`. 훅은 7~10vw 초대형, 자간 타이트(-0.03em대).
- **다크 스크린 패널**: 채팅·SQL·diff는 실제 도구처럼 생긴 다크 인셋 카드(신호등 dots + 타이틀바). SQL 신택스 컬러, diff는 +그린/−레드 행 하이라이트, 핵심 줄엔 골드 아웃라인.
- 표는 재무제표풍 원장(ledger) 스타일: 상단 2px 잉크 룰, 행 구분 얇은 선, 숫자 우측 정렬.
- 크기는 전부 vw/vh/clamp — 어느 해상도에서든 스케일.

### 4. 연출 (전 슬라이드)

- **순차 등장 스태거**: 슬라이드 진입 시 아이브로→헤드라인→본문→그림 순 60~130ms 간격 fade+rise. 카드·표 행·칩·박스는 개별 아이템 단위로. 항목이 많으면 간격을 자동 축소해 총 1초 안팎 유지.
- **타이핑**: 에이전트 채팅 패널의 사용자 질문은 커서와 함께 글자 단위 타이핑(26ms/자), 도구 호출·응답은 순차 등장. **에이전트 패널만 살아 움직이고 사람 검증 패널은 정적** — 구분 자체가 메시지다.
- **숫자 카운트**: 히어로 수치는 진입 시 카운트업/다운(`data-count-from/to/dur`, ease-out cubic). HTML엔 최종값을 박아 무연출 환경에서도 정상 표시.
- **팝**: 상징 글리프(≠ 등)는 scale(0→1.3→1) 바운스.
- 타이핑 중 이탈 시 원본 텍스트 보존(dataset에 백업). `prefers-reduced-motion`이면 연출 전부 생략. 모든 타이머/RAF는 슬라이드 전환 시 정리.

### 5. 발표자 보기

- V 토글: 본 창이 발표자 모드(슬라이드 미리보기 scale(.5) + **대본 큼직하게** + 경과 타이머 + "다음 →" 예고)가 되고, 청중용 창이 자동으로 새로 뜬다.
- 창 간 동기화: postMessage(자식/opener) + BroadcastChannel 이중화 — 어느 창에서 넘겨도 함께 넘어간다. file:// 환경에서도 동작해야 한다.
- **대본을 슬라이드 전체 분량으로 써서 JS 배열에 내장**하라. 발표자가 그대로 소리 내 읽을 수 있는 구어체 문장으로, 호흡 지시("(한 박자 쉬고)")까지. 시연 대본 문서가 있으면 그 멘트를 뼈대로 삼는다.

### 6. 작업 절차 (반드시 지켜라)

1. 시연 시나리오·실측 수치 문서를 **먼저 읽고** 숫자를 고정한다. 문서에 없는 숫자·이름·사례는 절대 만들지 않는다.
2. 덱 구성안(장별 한 문장 + 주인공 비주얼)을 표로 사용자에게 승인받는다.
3. 구현 후 **헤드리스 브라우저로 전 슬라이드 스크린샷**을 찍어 직접 보고 고친다: 텍스트 잘림·여백 과다·대비 부족·SVG 오버플로. 연출은 **중간 프레임**도 캡처해 실동작을 확인한다. 콘솔 에러 0이어야 한다.
4. 인쇄(PDF)와 축소 창에서도 확인한다.
5. 커밋은 단계별로 쪼갠다. 공개 저장소면 대용량 바이너리·영업 전략 문서가 딸려 들어가지 않는지 커밋 후 `git show --stat`으로 검수한다.

### 7. 부속 산출물

- **FAQ 대응 시트**(별도 .md): 예상 질문 10개 × (한 줄 답 → 상세 → 점프할 슬라이드 번호) + "답하지 말 것" 섹션(가격·기간 확답 금지 등). 본편 덱에는 절대 합치지 않는다.

### 8. 하지 말 것

- 템플릿 냄새: "01/02/03 번호 매기기 장식", 뻔한 그라데이션 히어로, 목적 없는 애니메이션 남발.
- 기존 PPTX식 정보 나열(제목+불릿 7개). 한 장에 메시지 둘 담기.
- 시연 스토리 곁가지 추가로 아크 늘이기 — 본편은 짧게, 욕심은 FAQ·부록으로.
