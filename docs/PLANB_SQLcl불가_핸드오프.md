# Plan B 핸드오프 — SQLcl 사용 불가 시나리오 (SRS/WBS 반영용)

> 작성: 2026-07-16, openwiki 세션에서 확정된 논의. SRS 리뷰·WBS 작성 세션에 전달.
> 상태: **리스크 대응 방향 합의됨. 확정 아님 — 선행 확인 1건(Bitbucket 채널) 남음.**

## 1. 상황 (사용자 실측)

- HCA DB는 AWS 폐쇄망 안쪽. 로컬/외부에서 DB 직결(SQLcl MCP 포함)이 **안 될 가능성 높음**.
- QA DB는 **데이터 정합성 없음** — 믿을 수 있는 건 소스와 DDL뿐.
- execute 권한도 불투명.

## 2. 핵심 재정의

**QA 데이터가 못 쓰는 순간, 라이브 DB 접속의 존재 이유가 소멸한다.**
라이브 접속이 필요한 유일한 기능은 데이터 evidence인데 데이터가 쓰레기면 얻을 게 없다.
남는 가치(소스, DDL, 딕셔너리)는 전부 **정적 텍스트** → 올바른 매체는 라이브 조회가 아니라 **파일 반출**.
따라서 "소스를 뜯어서 클라우드에 올리는 방식"은 차선책이 아니라 이 조건에서의 정답.

## 3. Plan B 구성

### 3.1 반출물 (폐쇄망 안쪽에서 스크립트 1방, 재실행 가능한 배치)

| 항목 | 소스 | 용도 |
|------|------|------|
| 패키지 소스 | `ALL_SOURCE` → 패키지별 .sql (헤드/바디 분리) | 역문서화 원료 (raw/code) |
| 테이블 DDL | `DBMS_METADATA.GET_DDL` | raw/code/schema |
| 컬럼 사실 | `ALL_TAB_COLUMNS` + `ALL_COL_COMMENTS` + `ALL_TAB_COMMENTS` → CSV | 의미→컬럼 역방향(A5), TBD 스키마 일괄 확정 |
| 제약/방향 | `ALL_CONSTRAINTS` + `ALL_CONS_COLUMNS` → CSV | FK 방향 검증 (P_SUBVENSION_HF류 방향 애매성) |
| 종속성 | `ALL_DEPENDENCIES` | 이미 확보(03_추출_대장, 위상순서) — 증분 시에만 재덤프 |

### 3.2 반출 채널 — **선행 확인 1순위**

- 증분 설계가 이미 "Bitbucket 유입 변경분 → Robotics"였음 = 소스가 폐쇄망 밖으로 나오는 승인된 통로가 존재(예정)한다는 뜻.
- **벌크 반출도 같은 Bitbucket 리포에 소스+딕셔너리 덤프를 커밋하는 방식이 최선** — 버저닝·증분·신선도 관리가 git으로 공짜, "동기화 매체=git" 원칙과 일치.
- 확인 필요: 그 Bitbucket이 폐쇄망 안인지 밖인지. 밖이면 승인 이슈 소멸, 안이면 미러 반출 승인이 크리티컬 패스.
- 소스 전량 클라우드 반출은 보안 승인 리스크 실존 — SRS 제약사항에 명기할 것.

### 3.3 execute — 범위 제외 권고

- 데이터가 안 맞는 DB의 실행 결과는 검증 수단이 아니라 노이즈원.
- 검증 2루프(로컬 채점 → 기대그래프 diff)는 원래 실행 없이 도는 설계.
- 런타임 검증이 필요해지면 "정합성 있는 테스트 데이터셋 확보"라는 별개 과제로 분리. 이 파이프라인에 엮지 않는다.

## 4. 아키텍처 영향

| 영역 | 영향 |
|------|------|
| 로컬 저작 루프 | 무영향. raw/가 클립보드 수동본 → 스크립트 덤프본으로 오히려 업그레이드 |
| 서버 3계층 (LightRAG=의미 / OKF=원문 / SQLcl=사실) | 사실 계층을 "라이브 SQLcl" → "딕셔너리 스냅샷 + okf/tables"로 교체. DDL은 정적이라 스냅샷이 그대로 권위. 데이터 사실 질의만 범위 제외(어차피 QA 데이터로는 죽어 있던 기능) |
| 전역 표준 "2 MCP(LightRAG+SQLcl)" | SQLcl 불가 확정 시 전역 CLAUDE.md·OKF 운영매뉴얼 갱신 대상 |
| 신선도 | 라이브 조회 대비 스냅샷은 낡음 — 덤프 추출일 기록 + 증분 시 해당 패키지 딕셔너리 재덤프를 절차에 포함 |

## 5. SRS/WBS 반영 포인트

**SRS:**
- 제약사항: "DB 라이브 접속 불가(폐쇄망)" + "QA 데이터 정합성 없음 → 데이터 기반 검증 범위 제외" + "소스 반출은 보안 승인 전제"
- 요구사항 변경: SQLcl MCP 의존 항목 → 딕셔너리 스냅샷 파일 기반으로 수정
- execute 관련 요구사항 있으면 제거 또는 별도 과제로 분리

**WBS 추가 태스크 후보:**
1. Bitbucket 반출 채널 확인 (폐쇄망 안/밖, 승인 상태) — **크리티컬 패스, 최우선**
2. 폐쇄망 내 딕셔너리+소스 일괄 덤프 스크립트 작성·검증 (재실행 가능 배치)
3. 반출 번들 → raw/ 재구성 (기존 클립보드 수동본 대체)
4. okf/tables 역할 승격 (A5·D3 담당을 SQLcl → 스냅샷+okf/tables로 이관)
5. 신선도 절차 명문화 (덤프 일자 기록, 증분 시 재덤프)
6. (SQLcl 불가 확정 시) 전역 CLAUDE.md·OKF 운영매뉴얼의 2 MCP 표준 갱신
