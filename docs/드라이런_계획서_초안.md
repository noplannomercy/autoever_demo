# 드라이런 계획서 (초안 v0.1)

> WBS 1.14 (마일스톤 M2) · 2026-07-16 · 시기: 8월 중순 (환경 불요 — Bedrock 개통과 무관하게 수행)
> 목적: 본작업 착수 전에 **파이프라인 전 구간이 실제로 도는지**를 리허설하고, 일정·품질 판단에 쓸 **실측 수치**를 확보한다.

## 1. 무엇으로 돌리는가 (입력 자산)

| 자산 | 내용 | 비고 |
|------|------|------|
| 기준 시스템 | 시연에 사용한 시스템 그대로 — 레거시 패키지, KB(LightRAG), 지식층(OKF) | 고객 시연으로 동작이 이미 확인된 자산 |
| 작성 지침 | OKF 역문서화 지침 (1.12 산출물) | KB 적재·질의 테스트 기검증 |
| 검증 기준 | 검증 기준서 (1.13 산출물) — L1 기계 대조 + L2 LLM 채점 + L3 표본 | 임계값 캘리브레이션이 드라이런의 목적 중 하나 |
| 관리 대장 | 대장 양식 (1.10 산출물) — 상태·점수·이력 기록 리허설 포함 | |
| (선택) 실제 패키지 표본 | 1.4 공식 반입 채널 확보 시 소수 표본 추가 | 미확보 시 기준 시스템 자산만으로 진행 |

## 2. 무엇을 돌리는가 (전 구간)

```
소스 준비 → 반입 검증(라인수 대조) → 역문서 생성(지침 적용)
  → L1 기계 대조 → L2 LLM 채점 → L3 사람 표본 검증
  → KB 적재 → 골든 질의 응답 확인
```

- 각 단계는 관리 대장에 상태·결과를 기록하며 진행한다 (운영과 동일한 방식의 리허설).
- 의도적으로 **불합격 문서 1건 이상을 만들어** 재생성 경로(R-08)까지 리허설한다.

## 3. 무엇을 재는가 (측정 항목과 쓰임새)

| # | 측정 | 쓰임새 |
|---|------|--------|
| M-1 | 패키지 1건당 단계별 소요 시간 (생성/검증/적재) | 처리량 산정 → **TBD-5(목표치)·2.3 일정(E+2~8주) 판정의 입력** |
| M-2 | 회차(≤15,000라인) 환산 처리 시간 | 2.3의 주당 회차 페이스 산출 — **A4(1인 수행) 조기 경보** |
| M-3 | L2 채점 점수 분포 ↔ L3 사람 판정 상관 | **합격 임계값 확정** (검증 기준서 미결 1·2) |
| M-4 | 골든 질의 초기 세트 도출 + 정답률 베이스라인 | R-18 측정 세트의 출발점 — **C2 목표치 논의의 근거** |
| M-5 | 실패 유형 목록 (생성 실패·검증 미달 사유) | 지침(1.12) 보강 포인트 |
| M-6 | 저지 모델·프롬프트 고정본 확정 | 채점 재현성 (검증 기준서 미결 3) |

## 4. 이 수치가 의미하지 않는 것 (한계 — 반드시 함께 읽을 것)

드라이런은 **설계 검증**이지 본작업 성능 보증이 아니다.

1. 입력이 다르다 — 기준 시스템 자산은 실제 payments 패키지(최대 2.4만 라인/개)와 규모·복잡도가 다르다.
2. 환경이 다르다 — 드라이런은 로컬/기준 환경, 본작업은 Bedrock(모델·쿼터 미확정, TBD-1).
3. 따라서 **본작업의 확정 수치(C1·C2 목표치, 처리량)는 Bedrock 개통 후 실제 패키지 샘플 5개 실측(WBS 2.2, M3)에서 확정**하며, 드라이런 수치는 그 이전의 계획 입력값이다.

이 구분은 SRS §6("측정 방식은 지금, 목표 수치는 실측 후")과 동일한 원칙이다.
