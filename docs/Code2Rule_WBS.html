구간별 태스크 상세

모든 태스크는 세트 문서 SRS v0.1의 요구사항(R-nn)·미확정 항목(TBD-n)에 근거한다. 담당 고객 태스크는 후속 일정의 선행 조건이다.

Phase 1 — 준비기 07.15 – 08.20 · 환경 없이 가능한 작업 · 이 구간 산출물이 실행 속도를 결정

1.1SRS 리뷰 미팅 — 아래 아젠다 합의 반영 시 v1.0 승격M1아젠다: ① 대상 범위 정정 합의(250 → 148, 운영계 재확정 절차 포함) ② 설계 원칙 P1~P6 · 유저스토리 추적표(부록 A) 확인 — 재해석·이연 항목(US-6 화면, US-8 승인, US-15 SSO) 명시 합의 ③ 완료 기준 C1~C4 측정 방식 합의(수치는 실측 후) ④ 가정 A1~A5 · 앵커 이동 시 재기준 조항 합의 ⑤ TBD 6건 → 담당·기한 딸린 후속 태스크로 확정(1.3 · 1.6~1.8 · 2.2) ⑥ 필수 스택·사실 계층 합의 — KB(LightRAG)+사실 계층(스키마·코드값 사실 접근)은 시스템 성립 조건(R-05·R-10·R-16④). 접근 수준(운영계 읽기 > QA 라이브 > 스냅샷)이 검증 범위와 품질 상한을 결정하며, C1·C2 목표치는 판정 결과(1.5) 기준으로 확정. 채널은 OpenCode 우선·LibreChat 대안 ⑦ AWS 운용 주체 지정(1.3ⓐ) — Bedrock 개통(E)과 운영기 존립의 선행 조건공동7월 하순SRS v1.0본 문서(WBS) 전달이 리뷰 미팅 요청 · 목표 수치는 M3에서 v1.1

1.3Bedrock 개통 — 앵커 E의 전제 · 실체는 AWS 운용 체계 수립ⓐ AWS 운용 주체 지정 — 이하 전부의 선행 조건(계정·사용자(IAM)·쿼터·비용을 상시 운용할 담당) ⓑ 계정·리전 확정, 사용자·권한 관리 체계 ⓒ 망·보안 승인(금융권 연계) ⓓ Bedrock 모델 액세스·쿼터 신청 ⓔ 비용 한도·모니터링 설정고객~8/20 필수운용 주체 지정 + 환경 접속 정보TBD-1 · 지연 시 §5 R-0 · 주체 미지정 시 R-0a

1.6상태 정의 확정 — 수행이 상태 모델 초안 제시, 고객은 확인만US-12가 참조한 “Lifecycle Definition” 시트의 실체 확인이 목적 — 시트가 있으면 공유, 없으면 수행 초안에 확인·수정만. 초안은 상태 목록(대상→추출→생성→검증→적재→갱신)+전이 규칙까지 정의: 전이 트리거는 파이프라인 이벤트의 자동 기록이며 수동 승인·UI 전이 단계는 없음(P5 무정지 — 사람 액션은 잡 재실행뿐, R-12). 기한 내 의견 없으면 초안 기준으로 진행고객7월 중확정 상태 정의TBD-2 (US-12) · 1.10 관리 대장과 연동 · 별첨: 확인서 1장
