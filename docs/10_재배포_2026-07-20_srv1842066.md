## 2. 실행 절차 (실제 실행 내역 — 차이점 위주)

전체 흐름은 docs/08 §2 + docs/09 §4와 동일. 아래는 이번에 달랐던 부분만.

### 2-1. PG (커스텀 빌드 생략)
```bash
docker pull pgvector/pgvector:pg16
docker run -d --name postgres-vector --restart unless-stopped \
  -e POSTGRES_PASSWORD=<PG_PASSWORD> -p 127.0.0.1:5434:5432 \
  -v postgres-vector-data:/var/lib/postgresql/data pgvector/pgvector:pg16
# DB 2개 + lightrag DB에 CREATE EXTENSION vector — 이후 docs/08 §2-2와 동일
```
데이터 적재 검증표 **★6/★5/★4 정확 일치** 확인.

### 2-4. LightRAG `.env` (재작성 정본 — 키 3종만 치환하면 그대로 사용 가능)

### 2-3-보완. ⚠️ pkg_collection 함수 설치 (docs/08에 없어서 최초 배포 때 누락 — 2026-07-20 저녁 발견·복구)

**데이터 적재만으로는 끝이 아니다.** `demo_legacy`에는 레거시 함수 5종(`pkg_collection` 스키마)이 있어야 시연 장면 3~6(원인 추적 → CREATE OR REPLACE 배포 → f_calc_penalty 재실행)이 성립한다. 킬러 질의 A/B/C는 테이블만 조회하므로 **함수가 없어도 전부 통과한다 — 검증 사각지대**였음.

```bash
# 반드시 버그판(.bug.sql = 시연 시작 상태)을 설치. pkg_collection.sql은 수정(정답) 버전.
docker exec -i postgres-vector psql -U postgres -d demo_legacy < /opt/autoever_demo/legacy_src/pkg_collection.bug.sql
# 검증: 함수 5종 + 장면 6 배포 전 기대값
docker exec postgres-vector psql -U postgres -d demo_legacy -c '\df pkg_collection.*'   # 5 rows
docker exec postgres-vector psql -U postgres -d demo_legacy -c 'SELECT pkg_collection.f_calc_penalty(63), pkg_collection.f_calc_penalty(7);'  # 1460000 / 340000
```

또한 **시연·테스트 후 데이터가 오염될 수 있다** (2026-07-20: 전날 챗봇 테스트로 계약 +10건·입금 +33건 증가 확인 — 갭 수치는 무사했으나 덱의 "3,000건"과 불일치). `01_demo_data.sql`은 멱등(전체 재생성)이므로 **시연 전 재적재로 원복**하는 것을 리허설 절차에 포함할 것. 재적재 후 함수는 남아 있지만(스키마 별도) 위 검증 2줄은 다시 실행.
