## 4. 테스트 질의 세트 (유형별)

### A. DB 검색 — postgres MCP 단독 ("사실 조회")

에이전트가 SQL만 실행해서 답하는 질의. 규정 지식 불필요. 워밍업 겸 MCP-DB 연결 확인용.

|---|---|---|
| A-1 | loan_contract 몇 건이야? | **3,000건** |
| A-2 | 이번 달 입금(deposit)은 총 몇 건이야? | deposit 전체 **2,104건** 기준 월 필터 집계 (SQL 조건이 답변에 표시) |
| A-3 | 현재 연체(delinquency) 상태인 계약은 몇 건이야? | **229건** |

### B. 도메인 규정 검색 — lightrag MCP 단독 ("지식 조회")

KB(회수규정 13장)만으로 답하는 질의. DB 접근 불필요. LightRAG WebUI에서 직접 돌려도 동일.

| # | 질의 | 기대 결과 |
|---|---|---|
| B-1 | 입금 충당 우선순위 순서가 뭐야? | **연체이자 → 이자 → 원금 → 수수료** + 회수규정_02 인용 |
| B-2 | NSF가 발생하면 어떻게 처리하고, 언제 연체로 전환돼? | NSF 처리 절차 + 연체 전환 기준 + 회수규정_04·03 인용 |
| B-3 | 중도해지 위약금은 어떻게 계산하고, 면제 대상은 누구야? | 위약금 산정식 + **VIP 면제 규정** + 회수규정_05 인용 |

### C. 합성 — postgres + lightrag 교차검증 ("규정 위반 탐지") ★ 킬러 질의

에이전트가 **규정(KB)을 먼저 찾고 → 그 규정을 SQL로 데이터에 적용해 위반 건을 스스로 탐지**. 시연의 핵심.

| # | 질의 | 기대 결과 | 검증 흐름 |
|---|---|---|---|
| C-1 | 이번 달 입금 중 충당 순서 규정을 위반한 건 있어? | **6건** | B-1 규정 조회 → 입금 충당 내역 SQL 대조 |
| C-2 | NSF인데 연체 전환 안 된 계약 찾아줘. | **5건** | B-2 규정 조회 → NSF·연체 테이블 대조 |
| C-3 | 이번 분기 중도해지 중 위약금 정책 위반 있어? | **4건, ₩3,440,000** | B-3 규정 조회 → 해지·위약금 데이터 대조 (VIP 면제 오적용 탐지) |

> **C가 곧 "Code2Rule"의 증명**: A(데이터)와 B(규정)를 따로 물으면 각각 반쪽인데, C에서 에이전트가 둘을 합성해 사람이 명시하지 않은 위반 건수를 찾아낸다. 답변 상단 **"Used N tools"** 를 펼쳐 postgres·lightrag를 오간 툴 호출 로그를 보여주는 것이 연출 포인트.

**권장 시연 순서**: A-1 (워밍업) → B-1 → C 3종 — "데이터만 → 규정만 → 합성"의 단계적 스토리.
