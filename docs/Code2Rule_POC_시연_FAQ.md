# Code2Rule POC 시연 — Q&A 대응 시트 (발표자용)

> 2026-07-11 · 덱: `Code2Rule_POC_시연.html` (22장, 본편 동결)
> 사용법: 질문 유형을 듣고 해당 항목의 **한 줄 답**부터 던진 뒤, 필요하면 상세·슬라이드 점프.

## Q1. "이거 그냥 챗봇 아닌가요? ChatGPT랑 뭐가 다르죠?"

**한 줄 답:** 규정만 답하면 챗봇이 맞습니다. 이건 규정과 **실데이터를 대조해서 위반을 찾아내고, 고치고, 스스로 검증**합니다 — 챗봇은 여기서 멈춥니다.

- 상세: KB 단독 질의(규정 Q&A)는 흔한 기술. 가치는 4막부터 — 규정 ↔ `deposit_detail`/`billing` 대조로 갭 6·5·4건을 사전 지식 없이 발견. 챗봇은 "규정이 뭐냐"에 답하고, 이건 "규정대로 되어 있냐"에 답함.
- 점프: **8장**(규정 ≠ 데이터), **16장**(스코어보드)

## Q2. "코드 수정 전에, 당장 이번 분기 오부과 4건은 어떻게 하나요?"

**한 줄 답:** 에이전트가 데이터도 정정합니다 — 회수규정_05 근거로 4건 UPDATE, 실행 전 계획 제시 → before/after 대조 → 재조회 0건 확인까지.

- 상세: 시연에선 코드 수정에 집중했지만, 원본 7막 대본에는 데이터 정정(5막) → 재검증(6막) 루프가 있음. WHERE 없는 UPDATE 금지, contract_id로 범위 한정, rowCount=4 보고.
- 점프: **19장**(안전장치 5수칙)

## Q3. "AI가 틀린 답을 지어내면(환각) 어떡하죠?"

**한 줄 답:** 없는 건 없다고 답하게 설계돼 있고, 시연에서 실제로 보여드렸습니다.

- 상세: 계약 999999 → "데이터에 없음", KB에 없는 규정 → "규정 미정의". 모든 답변에 근거 블록(데이터: 테이블·행 ID / 규정: 문서명) 의무 첨부 — 인용은 실제 검색된 문서만.
- 점프: **15장**(환각 점검)

## Q4. "우리 보안 환경(폐쇄망)에서 돌아가나요?"

**한 줄 답:** 오늘 보신 것과 동일한 사이클을 **폐쇄망 검증 환경에서, 운영에 준하는 규모로** 이미 검증했습니다.

- 상세: 시연 자체도 폐쇄망 VDI에서 브라우저(LibreChat) 접속만으로 가능한 구성. 읽기/쓰기 도구 분리, Bearer 인증, 승인 기반 실행.
- ⚠️ **표현 주의:** 타사 실적을 말할 때 회사 특정("실계약사")·라인수("3만 라인")·"운영 레거시에서 검증" 3종 금지. 각각 소스 무단 반출 / 남의 운영계 침범으로 읽힌다. 되물으면 → "폐쇄망 안에 같은 조건의 검증 환경을 두고 그 안에서 돌렸습니다. 코드는 외부로 나가지 않습니다."
- 점프: **21장**(검증 완료), **18장**(장비 목록)

## Q5. "오픈소스 조합인데, 실제 프로젝트에서 이대로 쓸 수 있나요?"

**한 줄 답:** 이대로 쓰자는 게 아닙니다 — 블록별로 고객사 표준(AWS 관리형)으로 **치환**하는 구조라서, 새로 만드는 일이 아니라 바꿔 끼우는 일입니다.

- 상세: LightRAG → 관리형 벡터/검색, Postgres → 표준 DB, MCP 서버 → 표준 프로토콜 유지. 핵심 자산은 도구가 아니라 "규정↔데이터↔코드 대조" 설계와 안전수칙.
- 점프: **18장**(장비 목록 마지막 문장)

## Q6. "실행형 Agent를 바로 도입하는 건 위험하지 않나요?"

**한 줄 답:** 맞습니다. 그래서 로드맵이 문서 생성 → 챗봇 → Read-only → 실행형 **4단계**고, 오늘 보신 건 최종 단계의 미리보기입니다.

- 상세: 단계마다 관문(인프라·보안·운영통제·감사) 통과가 전제. 현재 적용 가능한 1차 범위는 업무 문서 생성.
- 점프: **20장**(로드맵)

## Q7. "레거시가 Oracle 3만 라인인데, 코드를 어떻게 읽죠?"

**한 줄 답:** 코드를 직접 읽는 게 아니라 **역문서(코드에서 자동 생성한 문서)**가 코드의 대리자 역할을 합니다 — 문서가 코드에서 재생성되니 낡지 않습니다.

- 상세: 데모는 코드가 DB 안에 있어 직접 읽었지만, 실환경은 역문서 엔진 경유. 코드 배포 후 역문서 갱신·재적재가 운영 사이클에 포함 — "문서는 깨진다"는 문제의 해답.
- 점프: **10장**(주석 발견 장면에서 자연 연결)

## Q8. "온보딩이나 인수인계에도 쓸 수 있나요?"

**한 줄 답:** 네 — 에이전트가 사전 지식 없이 테이블 구조·함수·컬럼 의미를 스스로 파악하는 걸 보셨듯, 신규 입사자가 시스템을 익히는 속도가 그 속도가 됩니다.

- 상세: 8테이블 FK 관계 + 한글 컬럼 주석 + 함수 5개를 즉석 요약(원본 1막). 질문으로 배우는 온보딩.

## Q9. "이 시연, 실제로 되는 건가요? 연출 아니에요?"

**한 줄 답:** 덱의 대화·숫자는 리허설 실측 기록 그대로이고, 원하시면 지금 라이브로 보여드립니다.

- 상세: 2026-07-02 리허설에서 에이전트가 대본 없이 수기 정정 관행까지 스스로 추론(diff는 정답지와 동일 + 규정 인용 주석까지). 라이브 데모 준비 상태 상시 유지(stage/ 폴더 실행).
- 점프: **7장**(무대 전환의 "각색이 아니라" 문구 재소환)

## Q10. "도입하면 뭐가 얼마나 좋아지는데요?" (ROI)

**한 줄 답:** 오늘 보신 그대로입니다 — 2줄 확인에 2주 걸리던 사이클이 몇 분이 됐고, 5년간 아무도 몰랐던 ₩3,440,000 오부과를 첫 질문에 찾았습니다.

- 상세: 정량 수치는 고객사 업무량 기준 산정 필요(문의·장애·감사 대응 건수 × 건당 확인 시간). 섣부른 숫자 약속은 하지 않기 — "귀사 기준으로 같이 계산해 보자"로 전환.

## 답하지 말 것 / 주의

- **가격·기간 확답 금지** — 범위 산정 전. "1단계(문서 생성)부터 같이 범위를 잡자"로.
- **갭이 합성 데이터라는 언급 불필요** — 물으면 "시연용 재현 환경이고, 동일 사이클을 운영에 준하는 규모로 검증했다"(Q4·Q9)로.
- **타사 실적 표현 3종 금지** — 회사 특정("실계약사")·라인수("3만 라인")·"운영 레거시에서 검증". 소스 무단 반출 / 남의 운영계 침범으로 읽힌다. 대체 표현: "운영에 준하는 규모 · 폐쇄망 검증 환경 · 코드 반출 없음". (Q7의 "Oracle 3만 라인"은 고객사 본인 레거시 규모라 무관.)
- 모델/LLM 종류 질문 → "특정 모델 종속 아님, MCP 표준이라 교체 가능" 선에서.
