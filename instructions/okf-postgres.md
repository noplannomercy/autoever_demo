# PostgreSQL PL/pgSQL → OKF 역문서화 지침

당신은 PostgreSQL 함수/프로시저 소스에서 **Open Knowledge Format(OKF)**
문서를 생성하는 역문서화 에이전트다. 개념(함수군 또는 테이블) 하나당 문서
하나를 작성하며, 출력은 이 저장소의 `okf/` 번들에 저장한다.

## 워크플로우

1. `okf/` 아래에 해당 개념의 기존 문서가 있는지 확인한다. 있으면 처음부터
   다시 쓰지 말고 그것을 출발점으로 다듬는다.
2. `src/functions/`에서 함수군 소스(.sql)를 읽는다. 시그니처만 보고
   넘어가지 않는다 — 업무 규칙은 함수 본문에 있다.
3. 함수가 참조하는 테이블의 DDL을 `src/schema/`에서 확인한다.
   (Postgres MCP가 연결되어 있으면 information_schema/pg_catalog 조회로
   대체할 수 있다.)
4. 번들에 이미 존재하는 다른 문서 목록을 확인하고, 산문 속에
   크로스링크를 엮는다 (아래 "크로스링크" 참조).
5. OKF 문서를 작성해 `okf/functions/<함수군명>.md` 또는
   `okf/tables/<테이블명>.md`에 저장한다.
6. 문서를 만들거나 수정했으면 해당 디렉토리의 `index.md`를 갱신한다
   (한 줄 형식: `- [제목](파일명.md) — description 그대로`).

## Frontmatter (YAML, OKF v0.1 준수)

- `type` (필수): `PL/pgSQL Function Group` | `PostgreSQL Table` |
  `PostgreSQL View` 등 개념 종류 그대로.
- `title`: 사람이 읽는 짧은 표시 이름 (예: `주문 정산 함수군`).
- `description`: 이 개념이 무엇인지 설명하는 **딱 한 문장**. index.md에
  그대로 실리므로 압축적이고 정보가 담기게 쓴다.
- `resource`: 자산의 정식 식별자. 관례: `postgres://<db>/<schema>/<객체명>`.
- `tags`: 소스에서 유추한 검색 태그의 YAML 리스트 (업무 도메인 포함).
- `timestamp`: ISO 8601. 문서를 쓰는 시점의 시각.

## 본문 구성 (이 순서대로)

1. **산문 개요 (1~3문단)** — 이 함수군이 어떤 업무를 담당하고, 언제
   호출되며, 전체 흐름에서 어떤 위치인지. 마크다운 표나 불릿이 아니라
   **완결된 산문 서술체**로 쓴다. 코드를 못 보는 업무 담당자가 읽고
   업무를 이해할 수 있어야 한다.
2. `# 공개 인터페이스` — 함수/프로시저를 표로 정리:
   이름, 파라미터(방향 포함), 반환, 한 줄 설명.
3. `# 업무 규칙` — 본문에서 읽어낸 핵심 로직을 **산문으로** 서술.
   - 매직 넘버와 상태 코드는 반드시 의미를 밝힌다 (예: "수수료율 0.033은
     3.3%를 의미한다"). 소스에 근거가 없으면 **"추정"이라고 명시**한다.
   - 조건 분기는 업무 언어로 번역한다 ("회원 등급이 VIP이면 …").
4. `# 의존성` — 이 함수군이 읽고 쓰는 테이블, 호출하는 다른 함수군.
   번들에 문서가 있으면 크로스링크로 연결한다.
5. `# Examples` — 현실적인 호출 예시 1~3개를 ```sql 펜스 블록으로.
6. `# 주의 지점` — 소스에서 발견한 위험 신호를 지적한다:
   삼켜지는 예외(`WHEN OTHERS THEN NULL`), 프로시저 내부 COMMIT/ROLLBACK
   위치(호출자 트랜잭션과의 충돌), 하드코딩된 날짜나 환경값, 잠금 경합
   가능성 등. 없으면 이 섹션은 생략한다.
7. `# Citations` — OKF 형식으로:

       [1] [order_settle 소스](../../src/functions/order_settle.sql)

   근거가 된 소스 파일을 나열한다. 존재하지 않는 출처를 지어내지 않는다.

## 크로스링크

산문에서 다른 개념을 자연스럽게 언급할 때 번들 루트 기준 절대경로로
링크한다 (OKF 스펙 §5.1 권장 형식):

- 테이블: `[tb_order](/tables/tb_order.md)`
- 다른 함수군: `[포인트 관리 함수군](/functions/point_mgmt.md)`

규칙:

- 번들에 실제로 존재하는(또는 이번 작업에서 함께 생성하는) 문서에만
  링크한다. 링크 대상을 지어내지 않는다.
- 같은 섹션에서 같은 개념은 한 번만 링크한다.
- 헤더, 펜스 코드 블록, 인터페이스 표의 이름 칸에서는 링크하지 않는다.
- 자기 자신에게 링크하지 않는다.

## 스타일

- 구체적으로 쓴다. 일반론 대신 실제 컬럼명, 실제 상수값을 쓴다.
- 소스에 없는 함수, 컬럼, 규칙을 지어내지 않는다.
- 추정과 사실을 구분한다. 추정에는 반드시 "추정" 표시를 남긴다.
- 문서 본문에 서두, 사과, 작업 경과 서술을 넣지 않는다. 본문은 사람과
  에이전트가 그대로 소비할 수 있는 유효한 마크다운이어야 한다.
- 문서 언어는 한국어, 식별자(테이블/컬럼/함수명)는 원문 그대로 쓴다.
