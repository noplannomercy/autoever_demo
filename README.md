# Code2Rule — 레거시 DB 패키지 역문서화 · 지식베이스 기준 시스템

> 오라클 PL/SQL 패키지 안에 갇힌 비즈니스 로직을 **역문서화 → 지식베이스(KB) → AI 에이전트 합성**으로 꺼내는 파이프라인의 기준(reference) 시스템.
> "규정·데이터·코드, 이 셋이 서로 맞는지 아무도 자신 못 하는 상태"를 몇 분 단위 확인으로 바꾸는 것이 목적이다.

## 무엇이 들어있나

| 구성 | 경로 | 설명 |
|------|------|------|
| 시연 무대 | `stage/` | OpenCode 에이전트 실행 폴더 — 소스·지침·연결 설정만 (운영 담당자가 실제로 가질 파일) |
| 목업 레거시 | `legacy_src/` | 가상 여신/할부사의 DB 저장 패키지(`pkg_collection`) — 청구·연체이자·위약금·충당·연체전환. 버그 버전 골든카피 포함 |
| 합성 데이터 | `data/` | 고객 2,000 · 계약 3,000 · 상환스케줄 12,600 등 8개 테이블 (PostgreSQL) |
| 규정집 | `rules/` | 회수규정 13장 — KB(LightRAG) 적재용 |
| MCP 서버 | `lightrag-mcp/` `postgres-mcp/` | 에이전트 ↔ KB 검색 / DB 라이브 조회 연결부 |
| 배포 | `deploy/` | 외부 VPS 재현 배포 구성 (검증 완료) |

## 어떻게 동작하나 (3층 합성)

```
┌ 규정집 (LightRAG KB) ──── "어떻게 해야 하는가"
├ 업무 데이터 (PostgreSQL) ─ "실제로 어떻게 되어 있는가"
└ 레거시 코드 (DB 패키지) ── "실제로 어떻게 계산하는가"
```

에이전트가 세 층을 넘나들며 **문제 확인 → 원인 추적 → 코드 수정 → 배포 → 검증**을 수행하고, 사람은 매 단계 데이터로 검증한다 (원칙: "에이전트가 말하면, 사람이 데이터로 검증한다"). 채널은 두 가지 — OpenCode(로컬 에이전트, 로컬 지식과의 합성) / LibreChat(웹).

## 설계 원칙 (요약)

- **패키지가 유일한 단위** — 문서화·갱신·적재 모두 패키지 바디 단위 (배포 단위와 일치)
- **역문서는 산출물, 코드가 원천** — 수선하지 않고 통째 재생성·교체
- **층 분리** — 코드 사실(역문서) / 업무 지식(OKF 지식층) / 코드값(DB 라이브 조회)을 섞지 않음
- **무정지 파이프라인** — 승인 게이트 없음, 품질은 자동 검증(LLM 저지 + 기대 그래프 diff)과 표본 캘리브레이션이 담당
- **추정 금지** — 코드·DB로 확인 안 되는 것은 `[SME 확인 필요]` 태깅
